# Правила роботи агента в проєкті

Проєкт ведеться за SDD. Еталон — затверджена SRS v1.0 (spec/srs.md), spec/acceptance.feature, spec/traceability.md.

Агент:
- кожен тікет, етап чи ризик пов'язує з ID вимог (REQ-F-xxx, REQ-NF-xxx), критеріїв (AC-...) або сценаріїв (BDD-...);
- не вигадує функціональність, якої немає в SRS; якщо вимога неоднозначна — виносить її в окремий список «Питання до специфікації», а не в тікет;
- не змінює файли в spec/ без прямої вказівки;
- не приймає рішень GO / REVISE — лише готує матеріали для людини;
- результати записує як чернетки (draft) у docs/plan/.
- Для тікетів використовує лише мітки type:*; мітки duplicate, invalid, question і bug — лише за моєю вказівкою. Нові мітки не створює.

## Коміти
- Агент може створювати коміти лише для файлів у docs/plan/ та logs/agent-session-lab3.md.
- Формат повідомлення: `docs: [agent] <короткий опис>` (див. розділ «Конвенція комітів» нижче).
- Перед кожним комітом агент показує `git diff --cached` і текст повідомлення та чекає підтвердження.
- Агент НЕ створює коміти з префіксом `gate:`, НЕ комітить зміни в spec/, НЕ виконує git push, git merge, git rebase, git reset, не перемикає гілки.

## Конвенція комітів
Формат: `<префікс>: [<джерело>] <опис англійською>`.
Префікси: `spec:` специфікація, `test:` тести, `feat:` реалізація, `docs:` документація та журнали, `gate:` рішення контрольних точок.
Джерело: `[human]` — зміну вніс власник, `[agent]` — зміну вніс агент. Автор коміту в Git — власник.

## Зміни файлів
Агент змінює файли лише інструментом редагування, а не командами shell (`cat >>`, `sed -i`, скрипти запису у файли).

## Контроль зовнішніх дій і даних
- Зовнішні дії (створення чи зміна issues, полів і зв'язків у трекері) агент виконує лише за документом, у шапці якого стоїть статус «Затверджено». Перед дією агент перевіряє статус; якщо його немає, не виконує дію й повідомляє людину (RISK-22).
- Результати агента зберігаються файлами в репозиторії й не генеруються повторно. Обчислення (суми, критичний шлях, звірки таблиць) агент виконує скриптом, а не вручну. У журналі сесії поточної роботи (`logs/agent-session-*.md`) для кожного етапу зазначається модель (RISK-17).
- Закриваючи питання чи рішення (Q-xx, PR-xx, D-xx), агент шукає всі його згадки в `docs/plan/`, `spec/` і тілах issues (`grep`, `gh issue list --search`) і подає людині перелік знайденого. Перед кожним гейтом агент шукає закриті ID, позначки «чернетка» та старі назви файлів (RISK-19).
- Ідентифікатори й лічильники із зовнішніх систем (номери issues, зв'язки, значення полів Project) агент бере лише з виводу команди й наводить цю команду у звіті. Значення-заглушки агент не підставляє, доки людина не надала фактичні (RISK-21).
