# Правила роботи агента в проєкті

Проєкт ведеться за SDD. Еталон — затверджена SRS v1.0 (spec/srs.md), spec/acceptance.feature, spec/traceability.md.

Агент:
- кожен тікет, етап чи ризик пов'язує з ID вимог (REQ-F-xxx, REQ-NF-xxx), критеріїв (AC-...) або сценаріїв (BDD-...);
- не вигадує функціональність, якої немає в SRS; якщо вимога неоднозначна — виносить її в окремий список «Питання до специфікації», а не в тікет;
- не змінює файли в spec/ без прямої вказівки;
- не приймає рішень GO / REVISE — лише готує матеріали для людини;
- результати записує як чернетки (draft) у docs/plan/.

## Коміти
- Агент може створювати коміти лише для файлів у docs/plan/ та logs/agent-session-lr3.md.
- Формат повідомлення: `docs: [agent] <короткий опис>` (конвенція docs/git-workflow.md).
- Перед кожним комітом агент показує `git diff --cached` і текст повідомлення та чекає підтвердження.
- Агент НЕ створює коміти з префіксом `gate:`, НЕ комітить зміни в spec/, НЕ виконує git push, git merge, git rebase, git reset, не перемикає гілки.
